1. REQUIREMENTS ANALYSIS
--------------------------------------------------------------------------------
Topic: Data Parallelism, Geometric Decomposition, and Performance Benchmarking.
Objective: Given an image matrix F of size n x m and a convolution kernel C of
size k x k (where k is odd, e.g. 3 or 5), calculate the resulting matrix V(n, m)
using:
  - Sequential baseline
  - Parallel implementation with p threads using geometric decomposition:
      * Horizontal (Row-wise decomposition)
      * Vertical (Column-wise decomposition)
      * Block (2D Submatrix decomposition - Bonus variant)
      * Cyclic (Round-robin 1D stride decomposition - Bonus variant)

Constraints:
  - Language requirements: Java and C++ (at least C++11).
  - Explicit threads only: Direct creation of Thread/Runnable in Java and
    std::thread in C++. Thread pools / Executors are strictly prohibited.
  - C++ Memory Models: Must compare:
      * Static allocation (fixed compile-time capacity arrays).
      * Dynamic allocation (runtime heap allocation with int**).
  - Virtual Border (Clamping): Elements outside matrix boundaries are snapped to
    the nearest boundary element: f[-1, j] = f[0, j], f[n, j] = f[n-1, j], etc.
  - Measurement: Only computation time is measured (I/O is strictly excluded).
  - Benchmarking: 10 runs per test configuration with arithmetic mean reported.
  - Strict Correctness: Every parallel run output is verified against the
    sequential baseline output for identical input data.


2. DESIGN & ARCHITECTURE
--------------------------------------------------------------------------------
Data Structures:
  - Java: 2D primitive arrays (int[][]).
  - C++ (Dynamic): Dynamically allocated pointer-to-pointer heap arrays (int**).
  - C++ (Static): Statically allocated global 2D arrays in .bss segment
    (int F[MAX_N][MAX_M]) with MAX_N = MAX_M = 10005 to prevent stack overflow.

Decomposition Strategies:
  1. Horizontal (Row-wise):
     The n rows are partitioned across p threads. Thread id gets rows:
     startRow = id * (n / p) + min(id, n % p)
     endRow   = startRow + (n / p) + (id < n % p ? 1 : 0)
     Each thread iterates through all m columns for its allocated rows.

  2. Vertical (Column-wise):
     The m columns are partitioned across p threads. Thread id gets columns:
     startCol = id * (m / p) + min(id, m % p)
     endCol   = startCol + (m / p) + (id < m % p ? 1 : 0)
     Each thread iterates through all n rows for its allocated columns.

  3. Block (2D Subgrid Decomposition - Bonus):
     p is factored into a 2D grid pr x pc as close to a square as possible.
     Rows are divided into pr segments and columns into pc segments.
     Thread t computes a 2D submatrix [startRow, endRow) x [startCol, endCol).

  4. Cyclic (Round-Robin Stride Decomposition - Bonus):
     Implements delta(i, j) = (i * m + j) % p = t.
     Each thread t steps with stride p across the flattened index space:
     for (int idx = t; idx < n * m; idx += p) {
         int i = idx / m;
         int j = idx % m;
         V[i][j] = computeConvolution(F, C, i, j, n, m, k, radius);
     }

Border Clamping:
  Using std::clamp in C++ and Math.clamp in Java:
  r = clamp(i + a, 0, n - 1)
  c = clamp(j + b, 0, m - 1)

5. COMPARATIVE ANALYSIS & CONCLUSIONS
--------------------------------------------------------------------------------
A. Sequential vs. Parallel Execution:
  - On tiny workloads (TC1: 10x10), parallelization exhibits slowdown (Speedup < 1x).
    Thread creation and context-switching overhead (~1-3 ms) vastly exceeds the
    actual computation cost (~0.007-0.5 ms).
  - On medium and large workloads (TC2, TC5), parallel execution provides significant
    speedup (up to 3.02x on C++ and 2.31x on Java), demonstrating the effectiveness
    of geometric domain decomposition on multi-core processors.

B. Decomposition Strategies Comparison (Horizontal, Vertical, Block, Cyclic):
  - Horizontal Decomposition: Excellent performance for square and tall matrices
    (e.g., TC4: 10000 x 10) because memory is stored in row-major order.
    Contiguous cache lines are fully utilized by each thread.
  - Vertical Decomposition: Dominates on wide matrices (e.g., TC3: 10 x 10000,
    speedup 1.86x vs. 0.92x for horizontal) where columns provide enough width
    for thread allocation without thread starvation.
  - Block Decomposition (Bonus): Combines horizontal and vertical partitioning.
    Minimizes perimeter-to-area ratio of submatrices, which helps balance cache
    utilization when both dimensions are large.
  - Cyclic Distribution (Bonus): Interleaves cells across threads with stride p.
    Provides uniform load balancing regardless of data skew, but suffers slightly
    on cache locality compared to contiguous block slices.

C. C++ Dynamic vs. Static Allocation:
  - Static allocation (global contiguous 2D array in .bss) allows the compiler to
    generate constant row-offset addressing (index = i * MAX_M + j). On large matrices
    (TC5), static sequential execution is faster (4045 ms) than dynamic pointer-to-pointer
    allocation (4795 ms).
  - Dynamic allocation requires pointer indirection (dereferencing int**). However,
    dynamic allocation adapts to exact dimensions at runtime without memory waste.

D. Java vs. C++ Execution Speed:
  - C++ compiled with -O3 significantly outperforms Java:
    * TC2 Sequential: C++ Dynamic = 23.65 ms vs. Java = 121.75 ms (~5.1x faster).
    * TC5 Sequential: C++ Static = 4045 ms vs. Java = 7748 ms (~1.9x faster).
  - The performance advantage of C++ stems from low-level compiler optimizations
    (vectorization, inlining) and zero runtime overhead compared to JVM array bounds
    checks and garbage collection pauses.

E. Best Performing Variant for Each Matrix Size:
  - TC1 (10 x 10, k=3):
    * Winner: C++ Dynamic Sequential (0.0070 ms). (Thread overhead not justified).
  - TC2 (1000 x 1000, k=3):
    * Winner: C++ Dynamic Horizontal with p = 8 threads (10.14 ms, Speedup = 2.33x).
  - TC3 (10 x 10000, k=5 - Wide):
    * Winner: C++ Dynamic Vertical with p = 4 threads (2.96 ms, Speedup = 1.86x).
  - TC4 (10000 x 10, k=5 - Tall):
    * Winner: C++ Dynamic Horizontal with p = 8 threads (3.63 ms, Speedup = 1.59x).
  - TC5 (10000 x 10000, k=5 - Large):
    * Winner: C++ Static Horizontal with p = 16 threads (1561.39 ms, Speedup = 2.59x)
      and C++ Dynamic Vertical with p = 16 threads (1589.77 ms, Speedup = 3.02x).
