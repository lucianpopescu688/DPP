1. REQUIREMENTS & PROBLEM FORMULATION
--------------------------------------------------------------------------------
Given an image matrix F(n, m) and an odd convolution kernel C(k, k), compute the
result matrix V(n, m) using spatial 2D convolution:
  V[i, j] = Sum_{a=0}^{k-1} Sum_{b=0}^{k-1} F[clamp(i+a-r, 0, n-1), clamp(j+b-r, 0, m-1)] * C[a, b]
where r = floor(k / 2). Elements outside the boundary clamp to the nearest edge.

Constraints & Compliance:
- Languages: Java 21 & modern C++20.
- Explicit Threading: Only manual java.lang.Thread and std::jthread. (No pools/executors).
- C++ Memory Models: Dynamic heap (int**) vs. Static contiguous (.bss segment).
- Bonus Algorithms: Block decomposition (+2 pts) and Cyclic delta stride (+2 pts).
- Benchmarking Rules: Arithmetic mean of 10 external program executions (I/O excluded).
- Verification: Every run output is verified element-by-element against output_seq.txt.


2. ARCHITECTURE & DECOMPOSITION STRATEGIES
--------------------------------------------------------------------------------
1. Horizontal (Row-wise): Rows partitioned across p threads:
     [startRow, endRow) with startRow = id * (n/p) + min(id, n%p).
     Optimal for row-major cache lines in square/tall matrices.
2. Vertical (Column-wise): Columns partitioned across p threads:
     [startCol, endCol) with startCol = id * (m/p) + min(id, m%p).
     Prevents thread starvation in wide matrices (m >> n).
3. Block (2D Subgrid - Bonus): p factored into pr x pc grid (pr * pc = p, pr <= sqrt(p)).
     Allocates 2D tile [r0, r1) x [c0, c1). Minimizes perimeter-to-area memory traffic.
4. Cyclic (1D Stride - Bonus): delta(i, j) = (i * m + j) % p == id.
     Thread id steps with stride p across flattened indices. Perfect load balance.

5. COMPARATIVE ANALYSIS & CONCLUSIONS
--------------------------------------------------------------------------------
1. Sequential vs. Parallel (Amdahl's Law):
   - On tiny inputs (TC1: 10x10), threading overhead (~1-3 ms) exceeds compute (~0.005 ms),
     causing slowdowns (0.06x speedup).
   - On large inputs (TC2, TC5), execution time drops dramatically: TC5 drops from 7.3s
     to 1.17s (6.21x speedup), demonstrating strong scaling on physical cores.

2. Decomposition Variants Comparison:
   - Horizontal: Superior for square and tall matrices (TC4) due to contiguous row cache lines.
   - Vertical: Essential for wide matrices (TC3: 10x10000) where rows are too few to partition.
   - Block (Bonus): The overall champion for massive matrices (TC5), achieving 6.21x peak
     speedup because 2D subgrids minimize perimeter memory bus traffic.
   - Cyclic (Bonus): Excellent load-balancing across skewed data, but has lower cache locality
     due to striding across rows.

3. C++ Memory Models (Dynamic vs. Static):
   - Static Allocation (compile-time contiguous array in .bss) delivers the fastest absolute
     sequential (7302 ms vs 10544 ms) and parallel (1175 ms) execution on TC5 due to flat
     offset addressing and zero pointer indirection.
   - Dynamic Allocation (int**) adapts to exact runtime dimensions without memory padding,
     outperforming static on narrow matrices (TC4) where static allocation's 40 KB row stride
     causes cache misses.

4. Language Comparison (C++ vs. Java):
   - C++ compiled with -O3 outperforms Java by 1.6x - 2.6x across workloads (TC5 peak:
     1175 ms in C++ vs. 3073 ms in Java).
   - C++ benefits from direct compiler vectorization (AVX2), absence of JVM bounds checks,
     and deterministic memory control without garbage collection pauses.
