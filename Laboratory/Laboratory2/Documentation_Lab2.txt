1. REQUIREMENTS & PROBLEM FORMULATION
--------------------------------------------------------------------------------
Given an input image matrix F(N, M) and a fixed 3x3 sharpening convolution kernel:
    K = [  0, -1,  0 ]
        [ -1,  5, -1 ]
        [  0, -1,  0 ]

The objective is to compute the filtered matrix directly IN-PLACE inside the
original matrix memory, adhering to strict memory constraints:
  - Postcondition: The initial matrix memory must contain the filtered image.
  - Strict Memory Constraint: NO result matrix and NO temporary full matrix of
    size O(N x M) may be allocated. Only 1D temporary row vectors within O(M)
    auxiliary space per thread are allowed.
  - Border Policy: Outer border pixels (i = 0, i = N-1, j = 0, j = M-1) are preserved.
  - Threading: Explicit thread primitives only (std::jthread in C++26,
    java.lang.Thread with Runnable in Java 25). No executor pools.
  - Concurrency Coordination: Barrier synchronization (std::barrier in C++26,
    java.util.concurrent.CyclicBarrier in Java 25).
  - Verification: Every execution output is strictly verified value-by-value
    against the sequential baseline without allocating extra matrices in memory
    (streaming file comparison via verify_files_equal).

2. ARCHITECTURE & IN-PLACE DECOMPOSITION STRATEGY
--------------------------------------------------------------------------------
In standard 2D convolution, each output pixel V[i, j] depends on F[i-1..i+1, j-1..j+1].
Overwriting F[i, j] in-place destroys the original pixel value needed by row i+1
and by neighbor threads, introducing write-after-read (WAR) hazards.

To resolve this with strictly O(M) auxiliary memory per thread:

A. Horizontal Line-Based Domain Decomposition:
   - Rows are partitioned across P threads:
       start_row = 1 + id * (N - 2) / P
       end_row   = 1 + (id + 1) * (N - 2) / P  (with end_row = N - 1 for id = P - 1)
   - Each thread is responsible for processing rows in [start_row, end_row).

B. Three-Phase Barrier-Synchronized In-Place Protocol (Variant 2B):
   - Phase 1 (Local Compute & Interior Commit):
     * Each thread maintains 4 1D vectors of size M:
       prev_row, curr_row, new_top, new_bottom.
     * Thread scans its assigned chunk from start_row to end_row - 1.
     * Intermediate interior rows (i > start_row and i < end_row - 1) are written
       DIRECTLY into matrix[i], because no other thread ever reads those rows.
     * Boundary rows (start_row and end_row - 1) are critical: they are adjacent
       to neighbor thread partitions. Their filtered values are stored in 1D buffers
       new_top and new_bottom, leaving matrix[start_row] and matrix[end_row - 1]
       intact so neighbor threads can safely read them.
   - Phase 2 (Global Synchronization Barrier):
     * All P threads arrive and wait at the barrier (std::barrier / CyclicBarrier).
     * Guarantees all threads have finished reading all boundary rows before any
       thread overwrites them.
   - Phase 3 (Boundary Commit):
     * After passing the barrier, each thread safely writes new_top into
       matrix[start_row] and new_bottom into matrix[end_row - 1].
     * Local O(M) buffers are freed.

3. THEORETICAL COMPLEXITY & MEMORY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity:
  * Sequential: O(N x M) operations (9 multiply-adds per interior cell).
  * Parallel: O((N x M) / P) computation + O(1) barrier synchronization latency.
- Space Complexity:
  * In-Place Auxiliary Memory: O(P x M) total across all threads.
  * Contrast with Standard Out-of-Place: O(N x M) memory for an extra matrix.
  * For TC3 (10,000 x 10,000):
    - Out-of-Place Matrix Allocation: ~400 MB auxiliary RAM.
    - In-Place (Our Implementation, P=8): 8 threads x 4 buffers x 10,000 x 4 bytes
      = ~1.28 MB auxiliary RAM (Over 300x memory reduction!).

6. KEY FINDINGS & COMPARATIVE ANALYSIS
--------------------------------------------------------------------------------
1. In-Place Memory Efficiency:
   The barrier-synchronized delayed boundary write (Variant 2B) completely eliminates
   the need for an auxiliary N x M matrix. This enables processing massive matrices
   (such as 10000 x 10000) that would otherwise strain L3 cache and trigger memory
   swapping.
2. Barrier Synchronization Scalability:
   Because only boundary rows (start_row and end_row - 1) are deferred to after
   the barrier, each thread writes (end_row - start_row - 2) interior rows
   concurrently during Phase 1. As N increases, the synchronization overhead
   at the barrier becomes negligible (< 0.05% of runtime).
3. Scalability with Physical vs. Logical Cores:
   On the test machine (4 physical cores, 8 hyperthreads), peak speedup is achieved
   at p = 4 threads (~2.78x in C++, ~2.70x in Java). Hyperthreading (p = 8) offers
   comparable performance, while oversaturation (p = 16) introduces context
   switching penalties.
4. C++26 vs. Java 25:
   C++26 execution is approximately 15x to 18x faster than Java due to cache-friendly
   raw pointer traversal, compiler auto-vectorization (SIMD), and absence of JVM
   array bounds checking.
