1. REQUIREMENTS & PROBLEM FORMULATION
--------------------------------------------------------------------------------
Perform 2D image convolution directly IN-PLACE inside the original matrix memory
using a fixed 3x3 sharpening kernel:
    K = [  0, -1,  0 ]
        [ -1,  5, -1 ]
        [  0, -1,  0 ]

Key Constraints:
- Postcondition: Initial matrix must contain the filtered image.
- Memory Constraint: NO temporary N x M matrix. Strictly O(M) auxiliary space
  per thread (reusable 1D row buffers).
- Border Policy: Outer border pixels are preserved (unmodified).
- Concurrency: Explicit threads only (std::jthread / Thread with Runnable).
- Synchronization: Barrier synchronization (std::barrier / CyclicBarrier).
- Correctness: Every run is verified element-by-element against sequential output.


2. ARCHITECTURE: IN-PLACE DECOMPOSITION (VARIANT 2B)
--------------------------------------------------------------------------------
To prevent write-after-read hazards without allocating a full matrix:
1. Horizontal Row Partitioning:
   - Thread id processes rows [start_row, end_row).
2. Phase 1 - Local Compute & Direct Interior Commit:
   - Intermediate interior rows are computed and written directly into matrix[i].
   - Boundary rows (start_row and end_row - 1) adjacent to neighbor partitions
     are saved into 1D local buffers (new_top, new_bottom) to keep original
     values readable by neighbor threads.
3. Phase 2 - Synchronization Barrier:
   - All threads synchronize at the barrier (std::barrier / CyclicBarrier).
4. Phase 3 - Boundary Commit:
   - Each thread writes its buffered new_top and new_bottom into the matrix.

Memory Complexity: O(P x M) total auxiliary space vs O(N x M) for full matrix copy.
On 10,000 x 10,000, auxiliary memory is reduced from ~400 MB to ~1.3 MB (>300x less).

4. KEY CONCLUSIONS
--------------------------------------------------------------------------------
1. In-Place Efficiency:
   Barrier-synchronized delayed boundary writing (Variant 2B) completely avoids
   allocating a secondary N x M matrix, preventing memory exhaustion and cache
   thrashing on large matrices.
2. Barrier Scalability:
   Only boundary rows are delayed; all interior rows commit concurrently in Phase 1.
   Barrier overhead is negligible (< 0.1% of runtime on large matrices).
3. Core Scaling:
   Peak speedup is achieved at p = 4 threads (~2.78x in C++, ~2.70x in Java),
   matching the 4 physical CPU cores of the AMD Ryzen 7 3750H.
4. C++ vs. Java:
   C++26 is ~15-20x faster than Java due to direct pointer manipulation, compiler
   SIMD vectorization, and absence of JVM runtime overhead.
